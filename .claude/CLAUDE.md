# game-workspace

## 回答

- 必须用中文，称呼我为【我尊敬的领主大人】
- 不要 AI 腔：不客套、不复述问题、不说套话，直接说结论
- 做完事情要说明做了什么：改了哪些文件、各改了什么、哪些没做或没验证

## 做事

- 不确定的地方先问，不要猜着做
- 只做要求的事，不顺手改别的
- 删除或覆盖文件之前先问我，我明确说了要删、要改的除外
- 我定的文件名、目录名照原样用，跟规则冲突时先问我，不要建议改名
- 测试用的临时文件跑完就删；测试不访问网络，不用真实的 `games/games.list`

## Git

- 不准自己 commit 或 push，也不要主动问要不要提交。commit message 写好给我过目，由我自己提交
- 写 commit message 之前先用 `commit` skill

## 目录

- 游戏在这个工作区里开发，会话开在工作区根目录。工作区的规矩对游戏同样有效
- 游戏仓库里不放任何 Claude 相关的文件。游戏的约定写在游戏仓库自己的 README 和它链接的文档里，工作区不写具体某个游戏的规矩；跟工作区冲突时先问我
- 根目录里进 git 的文件只放 `Makefile`、`README.md` 和 git 相关的
- 针对某类文件的规范放在 `.claude/rules/`，用 `paths:` 按需加载，文件名用 `style.<内容>.md`（怎么写）或 `dir.<目录>.md`（某个目录的规矩）；针对某种操作的规矩（比如提交）放在 `.claude/skills/`
- 新开的游戏在 `games/games.list` 登记（`make add`）
- 私有游戏的名字和相关内容不写进任何被 git 跟踪的文件和 commit message
