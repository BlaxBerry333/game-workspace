# 游戏

- 改 `games/<游戏名>/` 下的文件之前，先读这个游戏根目录的 `README.md`，以及要改的平台目录（比如 `apps/web/`）的 `README.md`，再按里面的链接读跟这次改动有关的文档，按里面的约定做。文档有英文版和中文版（`*.zh-CN.md`）时读英文版
- 游戏根目录的 Makefile 提供 `help`（`make` 不带命令时的默认）、`dev`、`build`、`test`；有初始化（装依赖、复制本地配置）的再提供 `setup`，跑几次结果都一样。工作区的 `make <命令> game=<游戏名>` 只转发 `dev`、`build`、`test`、`setup`
- Makefile 只登记入口，逻辑写在游戏仓库根目录的 `scripts/`，写法见 `style.scripts.md`
- 进度和计划（路线、顺序、风险）写在工作区根目录的 `TODO.md`（不进 git），游戏仓库里不放计划。每个游戏一大节，至少分「现在在做」「接下来」，还没有就先加上。动手前先读；开始做一项就挪到「现在在做」，做完就删掉。只写现在的状态，不写经过
