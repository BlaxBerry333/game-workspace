# web 游戏

项目的 README 和它链接的文档跟这里冲突时先问我。画面适配见 `style.web-screen.md`。

## 结构

- 画面、角色和游戏逻辑都不经过 React，React 只负责叠在画面上的 UI
- 游戏逻辑按固定步长（1/60 秒）更新：移动、碰撞放固定步长的更新里；动画、镜头、插值放每帧的更新里。随时间变化的量都乘 `dt`，不按帧计数
- 每帧的 `dt` 限制在 0 到 0.25 秒之间：切回标签页后不会一口气补跑上百次逻辑，时间戳往回走时也不会算出负数
- 按键先转成「动作」（移动、跑、攻击……），游戏代码只处理动作，不直接读按键。键位集中在一张表里，画面上的操作说明从这张表生成
- 速度、动画名这类参数放在配置里，不写死在代码中。动画按名字取，不按序号取
- 会让人移动的动作（翻滚、冲刺攻击、击退）用动画自带的位移：把 root 骨骼的水平位移从动画里取出来，动画原地播，位移交给代码按逻辑步移动角色
- three.js 以项目锁定的版本为准：参考同版本 GitHub tag 下的 examples 源码，不凭记忆写；不用带下划线的私有 API

## 画面切换和网址

- 不用路由。启动、标题、加载、游戏中、暂停、设置都是游戏内部的状态，用状态机切换
- 网址只用查询参数，当开发和分享用的开关，比如 `?debug`、`?lang=ja`、`?scene=…`、`?quality=…`
  - 启动时读一次，之后不往网址里写东西
  - 只认白名单里的参数和值，其他的忽略
  - 不放存档、进度这类数据

## 素材

- 放哪、命名、许可、怎么加载见 `dir.web.md`
- 模型用 GLB。颜色贴图标 sRGB，法线、粗糙度这类数据贴图保持线性
- 换角色模型时，用游戏里实测脚着地时的滑动量来定走、跑速度，不靠目测

## 调试和验证

- 开发时显示调参面板和帧率，只在开发时加载，正式打包里没有。游戏状态挂在 `window.<游戏名>` 上，在 console 里能直接读写
- 改了玩法之后在浏览器里验证：往 `window` 派发带 `code` 的 `KeyboardEvent` 模拟按键，读位置、状态、动画权重，再截图看画面
- 浏览器在后台时 requestAnimationFrame 会停。要验证时先停掉真实的循环（`renderer.setAnimationLoop(null)`），再手动推进主循环，时间戳每次加 1000/60；换成 1000/30、1000/144 能检查帧率无关。验证完恢复真实的循环
